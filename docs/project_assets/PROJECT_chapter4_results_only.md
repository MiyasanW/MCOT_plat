# บทที่ 4
# ผลการปฏิบัติงาน

จากการดำเนินโครงงานพัฒนาระบบจองอุปกรณ์ถ่ายทำและสตูดิโอออนไลน์ ณ บริษัท อสมท จำกัด (มหาชน) ผู้จัดทำสามารถพัฒนาและส่งมอบระบบที่รองรับการทำงานจริงของหน่วยงานได้ตามขอบเขตที่กำหนด โดยผลการปฏิบัติงานในบทนี้นำเสนอเฉพาะผลลัพธ์ที่เกิดขึ้นจากการพัฒนาและการใช้งานระบบจริง ดังรายละเอียดต่อไปนี้

## 4.1 การไหลงานและกระบวนการใช้งานระบบ
ระบบที่พัฒนาขึ้นมีการไหลงานหลักดังนี้

### 4.1.1 สถานการณ์ที่ 1: ลูกค้าจองทรัพยากร
ลูกค้าเข้าระบบและค้นหาตามความต้องการ เช่น ค้นหา "อุปกรณ์ไฟฟ้า" หรือ "สตูดิโอ" จากนั้นดูรายละเอียด ตรวจสอบความพร้อมใช้งาน (availability) ในช่วงวันที่ต้องการ เมื่อพร้อมจะเพิ่มรายการลงตะกร้า สามารถเลือกหลายรายการพร้อมกัน หลังจากเพิ่มครบตามต้องการ ลูกค้าจะดำเนินการยืนยันการจองและกรอกรายละเอียดผู้จอง เช่น ชื่อ อีเมล หมายเลขติดต่อ และวัตถุประสงค์ของการจอง

เมื่อลูกค้าส่งการจองจากหน้า "ยักษ์ยืนการจอง" ระบบจะสร้างรายการจองขึ้นและคำนวณมัดจำโดยอัตโนมัติ (ตั้งแต่ 20% ถึง 40% ของยอดรวม ขึ้นอยู่กับการตั้งค่า) พร้อมส่งอีเมลแจ้งให้ลูกค้าทราบว่าการจองได้รับการยืนยัน พร้อมแนบใบเสนอราคา (PDF) ที่มีรายละเอียดทรัพยากร วันที่เช่า ยอดรวม และยอดมัดจำ

(ใส่รูปภาพที่ 4.1 หน้าจอค้นหาและเลือกอุปกรณ์ในแคตตาล็อก)

(ใส่รูปภาพที่ 4.2 หน้าจอตะกร้าหลังเพิ่มรายการ และหน้าปาก "ยืนยันการจอง" พร้อมแสดงมัดจำและวันส่งมอบ)

### 4.1.2 สถานการณ์ที่ 2: เจ้าหน้าที่ตรวจสอบและอนุมัติ
เมื่อคำขอจองเข้ามา เจ้าหน้าที่จะได้รับแจ้งเตือนผ่านระบบ หลังจากตรวจสอบข้อมูลและความพร้อมของทรัพยากร (เช่น ว่างจริง ไม่มีข้อขัดของ) เจ้าหน้าที่จะเข้าไปในหน้าจอจัดการจอง (Staff Dashboard) เลือกการจอง และคลิกอนุมัติ ระบบจะตรวจสอบว่าสามารถอนุมัติได้หรือไม่ หากไม่มีปัญหา สถานะจะเปลี่ยนเป็น "Approved" และส่งอีเมลแจ้งโปรแกรมเมอร์ว่ารายการดำเนินการเรียบร้อย

(ใส่รูปภาพที่ 4.3 หน้า Staff Dashboard พร้อมแสดงรายการจองรอการตรวจสอบ)

### 4.1.3 สถานการณ์ที่ 3: ลูกค้าชำระเงินและอัปโหลดสลิป
หลังจากได้รับอีเมลใบเสนอราคา ลูกค้าจะทราบยอดมัดจำที่ต้องชำระ ลูกค้าไปชำระจำนวนนี้ไปยังบัญชีที่ระบุในใบเสนอราคา เมื่อชำระเสร็จแล้ว ลูกค้าจะเข้าระบบและไปที่หน้า "รายการจองของฉัน" (My Bookings) เลือกรายการที่ต้องการ และคลิก "อัปโหลดสลิปชำระเงิน" จากนั้นเลือกไฟล์ภาพสลิป หลังอัปโหลดเสร็จ ระบบจะบันทึกไฟล์และแสดงตัวอักษรรอตรวจสอบ

ส่วนเจ้าหน้าที่จะเห็นสลิปที่อัปโหลดมา ตรวจสอบจำนวนเงินกับใบเสนอราคา และหากถูกต้อง จะคลิก "ยืนยันการชำระเงิน" (Confirm Payment) ระบบจะอัปเดตสถานะเป็น "Paid" และส่งอีเมลแจ้งลูกค้าว่าการชำระนั้นได้รับการยืนยัน พร้อมแจ้งรายละเอียดการนำส่ง (วัน เวลา สถานที่รับ สิ่งที่ต้องเตรียมตัว)

(ใส่รูปภาพที่ 4.4 หน้า "My Bookings" พร้อมปุ่มอัปโหลดสลิปและสถานะการชำระ)

(ใส่รูปภาพที่ 4.5 หน้า Staff Dashboard ส่วนการยืนยันชำระเงินพร้อมแสดงสลิปที่อัปโหลดมา)

### 4.1.4 สถานการณ์ที่ 4: จัดเตรียมและนำส่งทรัพยากร
ในวันที่นำส่ง เจ้าหน้าที่จะเตรียมอุปกรณ์ตามรายการจอง บันทึกเลขที่ครุภัณฑ์ สภาพการแพ็ก และคนที่นำส่ง (หากจำเป็น) ในหน้า Staff Dashboard เมื่อครบส่วนแล้ว จะคลิก "เสร็จสิ้นรายการ" (Mark as Complete) ระบบจะอัปเดตสถานะเป็น "Completed" และส่งอีเมลยืนยันให้লูกค้า พร้อมแจ้งว่าการจองสิ้นสุดลง และหากมีระยะเวลาหลังคืนอุปกรณ์จะติดต่อเจ้าหน้าที่เพื่อกำหนดเวลารับ

(ใส่รูปภาพที่ 4.6 หน้า Staff Dashboard ส่วนการจัดเตรียม พร้อมฟิลด์เลขครุภัณฑ์และสภาพการ)

## 4.2 การส่งอีเมลใบเสนอราคาและการแจ้งเตือน
ระบบได้รวมกลไกการส่งอีเมลอัตโนมัติสำหรับสถานการณ์สำคัญต่างๆ เพื่อให้ลูกค้าและเจ้าหน้าที่ได้รับข้อมูลอย่างทันท่วงที

### 4.2.1 อีเมลใบเสนอราคา
เมื่อลูกค้าส่งการจองจาก "หน้ายืนยันการจอง" ระบบจะสร้างไฟล์ PDF ที่มีข้อมูล:
- รายชื่อและจำนวน อุปกรณ์/สตูดิโอ/บริการ ที่จอง
- ราคาต่อวัน ชำนวนวัน และยอดรวม
- ยอดมัดจำ (คำนวณตามเปอร์เซ็นต์ที่กำหนด)
- วันที่เอา วันที่คืน เวลาที่กำหนด
- บัญชีธนาคารสำหรับฝากมัดจำ
- เงื่อนไขการยบเพ่งหรือการปฏิเสธอื่นๆ

จากนั้นอีเมลนี้จะถูกส่งไปยังที่อยู่อีเมลลูกค้าทันที พร้อมแจ้งความต้องการในการดำเนินการต่อไปและระยะเวลาในการชำระเงิน

(ใส่รูปภาพที่ 4.7 ตัวอย่างไฟล์ PDF ใบเสนอราคา พร้อมแสดงรายละเอียดและยอดมัดจำ)

### 4.2.2 การแจ้งเตือนให้เจ้าหน้าที่
เมื่อมีการจองใหม่เข้ามา เจ้าหน้าที่จะได้รับการแจ้งเตือน (notification) ในระบบว่ามีการจองที่ต้องตรวจสอบ เมื่อเจ้าหน้าที่คลิก "ตรวจสอบ" จะไปยังหน้าแสดงรายละเอียดการจองและสามารถบันทึกความเห็น (comment) หรือขอข้อมูลเพิ่มเติมจากลูกค้าได้

นอกจากนี้ ระบบยังส่งอีเมลแจ้งเจ้าหน้าที่เมื่อมีการอัปโหลดสลิปชำระเงิน เพื่อให้บุคลากรตรวจสอบและยืนยันได้อย่างทันท่วงทีที่สุด

(ใส่รูปภาพที่ 4.8 หน้าแจ้งเตือนในระบบและ Dashboard ของเจ้าหน้าที่)

## 4.3 ผลการทดสอบระบบ
ผลการทดสอบในช่วงส่งมอบงานแสดงให้เห็นว่าระบบสามารถทำงานได้ตามเกณฑ์ที่กำหนด โดยการตรวจสอบโครงสร้างระบบด้วยคำสั่ง `python3 manage.py check` ผ่านเกณฑ์ และชุดทดสอบ (test suite) ที่เกี่ยวข้องกับการยืนยันตัวตน (authentication) การจอง (booking) และการยกเลิกรายการ (cancellation) ผ่านตามเงื่อนไขสำคัญแล้ว

ความสำเร็จของชุดทดสอบสำคัญ:
- **Authentication Tests**: ทดสอบว่าผู้ใช้แต่ละบทบาท (guest, customer, staff, admin) สามารถเข้าระบบและเข้าถึงเฉพาะหน้าที่สิทธิ์ของตนได้
- **Booking Tests**: ทดสอบการสร้างรายการจองจากตะกร้า การตรวจสอบความขัดแย้งของวันเวลา และคำนวณมัดจำ ผ่านทุกกรณี
- **Cancellation Tests**: ทดสอบการยกเลิกในแต่ละช่วงสถานะ (ก่อนอนุมัติ หลังอนุมัติ หลังชำระเงิน) และระบบคำนวณเงินคืนถูกต้อง
- **PDF Generation**: ทดสอบการสร้างใบเสนอราคา (quotation) และเอกสารอื่น ปรากฏครบถ้วนและเก็บไฟล์ได้

นอกจากนี้ กรณีทดสอบเชิงฟังก์ชันหลัก เช่น การสร้างรายการจองจากตะกร้าปกติ การปฏิเสธข้อมูลที่ไม่ถูกต้อง การควบคุมสิทธิ์การเข้าถึงจุดเชื่อมต่อของเจ้าหน้าที่ และการตรวจสอบช่วงเวลาที่ชนกันของการจอง ให้ผลลัพธ์สอดคล้องกับที่คาดหวังทั้งหมด สะท้อนว่าระบบมีความถูกต้องในกระบวนการสำคัญและพร้อมต่อการใช้งานในงานจริง

(ใส่รูปภาพที่ 4.9 ภาพผลการรันคำสั่งตรวจระบบ `python3 manage.py check` แสดงผ่านทั้งหมด)

(ใส่รูปภาพที่ 4.10 ตาราง/ภาพสรุปผลการทดสอบกรณีใช้งาน เช่น TC-01 สร้าง booking สำเร็จ, TC-02 rejection เมื่อวันขัดแย้ง, TC-03 permission denied สำหรับ staff API เมื่อ user ธรรมชาติ)

## 4.4 ผลการนำระบบขึ้นใช้งานจริง
ระบบถูกนำขึ้นใช้งานจริงบนเครื่องแม่ข่ายเสมือน (VPS) และสามารถให้บริการได้ต่อเนื่องภายใต้การตั้งค่าความปลอดภัยที่เหมาะสมกับสภาพแวดล้อม production โดยผลการตรวจสอบหลัง deploy พบว่าเส้นทางการใช้งานหลักของระบบทำงานได้ตามปกติ ทั้งฝั่งผู้ใช้งานทั่วไปและฝั่งเจ้าหน้าที่

เมื่อพิจารณาในภาพรวม ระบบสามารถรักษาความเสถียรในการให้บริการ รองรับการปฏิบัติงานประจำวันของหน่วยงาน และรองรับขั้นตอนตรวจสอบก่อนใช้งานจริงได้ตามแนวปฏิบัติที่กำหนด

(ใส่รูปภาพที่ 4.11 ภาพหน้าจอหน้าเว็บระบบหลังนำขึ้นใช้งานจริง พร้อมแสดง Header และ Footer ที่สมบูรณ์)

(ใส่รูปภาพที่ 4.12 ภาพผลการตรวจสถานะบริการบน VPS เช่น `systemctl status gunicorn` หรือ `ps aux | grep gunicorn` แสดงว่าบริการทำงานอยู่)

## 4.5 ผลลัพธ์เชิงประสิทธิภาพการทำงาน
หลังจากนำระบบมาใช้งาน พบผลลัพธ์เชิงประสิทธิภาพที่ชัดเจนในหลายมิติ ได้แก่ การลดจำนวนช่องทางการรับคำขอให้เหลือช่องทางหลักผ่านระบบเดียว การเปลี่ยนการตรวจสอบคิวและสต็อกจากการตรวจด้วยมือเป็นการตรวจผ่านระบบอัตโนมัติ การเพิ่มความชัดเจนในการติดตามสถานะรายการ และการทำให้ขั้นตอนอนุมัติมีลำดับงานที่เป็นมาตรฐานมากขึ้น

นอกจากนี้ หน่วยงานสามารถเรียกดูข้อมูลธุรกรรมและจัดทำข้อมูลสรุปได้สะดวกขึ้นจากฐานข้อมูลกลาง ส่งผลให้การประสานงานภายในมีความรวดเร็วและลดภาระงานซ้ำซ้อนเมื่อเทียบกับวิธีปฏิบัติเดิม

(ใส่รูปภาพที่ 4.13 ตารางเปรียบเทียบก่อนใช้ระบบและหลังใช้ระบบ)

(ใส่รูปภาพที่ 4.14 กราฟหรือ Dashboard สรุปจำนวนรายการจองต่างสถานะ (Approved, Paid, Completed, Cancelled) ในรอบเวลาที่ระบุ)

## 4.6 สรุปผลการปฏิบัติงานของบท
ผลการปฏิบัติงานในบทนี้ยืนยันว่าระบบที่พัฒนาขึ้นสามารถใช้งานได้จริงตามเป้าหมายของโครงงาน โดยให้ผลลัพธ์เชิงบวกทั้งด้านความครบถ้วนของฟังก์ชัน ความถูกต้องของการทำงาน ความพร้อมใช้งานในสภาพแวดล้อมจริง และประสิทธิภาพของกระบวนการปฏิบัติงานของหน่วยงาน เมื่อพิจารณาจากผลการทดสอบและผลการใช้งานจริง ระบบมีความพร้อมสำหรับการใช้งานต่อเนื่องและเป็นฐานสำคัญสำหรับการพัฒนาระบบในระยะถัดไป

(ใส่รูปภาพที่ 4.15 ภาพรวมการไหลงานตั้งแต่การจองจนถึงปิดงานแบบสรุป พร้อมแสดงสถานะหลักและอีเมลแจ้งเตือน)

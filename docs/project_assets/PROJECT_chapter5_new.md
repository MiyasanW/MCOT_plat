# บทที่ 5
# สรุปผลและข้อเสนอแนะ

จากการดำเนินโครงงานสหกิจศึกษาเรื่องระบบจองอุปกรณ์ถ่ายทำและสตูดิโอออนไลน์ ผู้จัดทำได้ปฏิบัติงานตามแผนที่กำหนดไว้ตลอดระยะเวลาการฝึกปฏิบัติงาน ณ บริษัท อสมท จำกัด (มหาชน) โดยมุ่งพัฒนาระบบให้สอดคล้องกับกระบวนการทำงานจริงของหน่วยงานทั้งในมิติการให้บริการ การจัดการข้อมูล และการควบคุมขั้นตอนการปฏิบัติงาน ผลการดำเนินงานโดยภาพรวมแสดงให้เห็นว่าระบบสามารถรองรับภารกิจหลักได้ตามวัตถุประสงค์ และสามารถนำไปใช้ประโยชน์เชิงปฏิบัติได้จริงในองค์กร ดังรายละเอียดต่อไปนี้

## 5.1 สรุปผล
ผลการดำเนินโครงงานพบว่า ระบบที่พัฒนาขึ้นสามารถทำงานได้ครอบคลุมกระบวนการหลักของงานเช่า ตั้งแต่การค้นหาและเลือกทรัพยากร การตรวจสอบความพร้อมใช้งาน การสร้างรายการจอง การชำระเงินและแนบหลักฐาน ตลอดจนการตรวจสอบและอนุมัติรายการโดยเจ้าหน้าที่ในแต่ละขั้นตอนอย่างเป็นลำดับ ส่งผลให้กระบวนการที่เดิมกระจายหลายช่องทางถูกปรับให้อยู่ในระบบเดียว มีความชัดเจนมากขึ้น และตรวจสอบย้อนหลังได้สะดวกขึ้น

ในเชิงผลลัพธ์การใช้งาน ระบบช่วยลดภาระงานซ้ำซ้อน ลดโอกาสผิดพลาดจากการจัดการข้อมูลด้วยมือ และเพิ่มความรวดเร็วในการติดตามสถานะรายการสำหรับทั้งลูกค้าและเจ้าหน้าที่ นอกจากนี้ ผู้จัดทำยังได้วางแนวทางรองรับการใช้งานจริงในระดับ production ทั้งด้านการจัดการสิทธิ์ผู้ใช้ การตั้งค่าความมั่นคงปลอดภัย และขั้นตอนตรวจสอบระบบก่อน-หลังนำขึ้นใช้งาน ซึ่งเป็นผลลัพธ์สำคัญที่สะท้อนความพร้อมของระบบและคุณค่าที่เกิดขึ้นกับหน่วยงาน

## 5.2 อภิปรายผล
จากผลการปฏิบัติงาน สามารถอภิปรายได้ว่าความสำเร็จของโครงงานไม่ได้เกิดจากการพัฒนาโปรแกรมเพียงอย่างเดียว แต่เกิดจากการบูรณาการองค์ความรู้ทางวิชาการกับบริบทการทำงานจริงในองค์กร โดยเฉพาะการทำความเข้าใจกระบวนการเดิม การเก็บข้อกำหนดจากผู้ใช้งานหลายบทบาท และการปรับปรุงระบบอย่างต่อเนื่องตามข้อเสนอแนะที่ได้รับในแต่ละช่วงการพัฒนา

ในมิติทางเทคนิค การแยกตรรกะธุรกิจออกจากส่วนควบคุมการทำงานช่วยเพิ่มความยืดหยุ่นในการบำรุงรักษาและลดผลกระทบเมื่อมีการเปลี่ยนเงื่อนไขทางธุรกิจ ขณะที่ในมิติผู้ใช้งาน การกำหนดขั้นตอนงานอย่างเป็นระบบและการแสดงสถานะที่ชัดเจนมีส่วนช่วยลดความคลาดเคลื่อนในการสื่อสารระหว่างฝ่าย อย่างไรก็ตาม ระบบในองค์กรจริงยังมีการเปลี่ยนแปลงความต้องการอยู่เสมอ จึงจำเป็นต้องรักษาสมดุลระหว่างความเร็วในการส่งมอบ คุณภาพของซอฟต์แวร์ และความพร้อมในการต่อยอดระยะยาว

## 5.3 วิเคราะห์ปัญหา สาเหตุของปัญหา และแนวทางการแก้ไขปัญหา

### 5.3.1 วิเคราะห์ปัญหาที่เกิดขึ้น
1) ข้อมูลธุรกรรมบางกรณีไม่สอดคล้องกันระหว่างข้อมูลในตะกร้าและข้อมูลล่าสุดในฐานข้อมูล

2) พฤติกรรมของระบบบางส่วนแตกต่างกันระหว่างสภาพแวดล้อมพัฒนา (local) และสภาพแวดล้อมใช้งานจริง (production)

3) กระบวนการเปลี่ยนสถานะรายการมีหลายเงื่อนไขและเกี่ยวข้องกับผู้ใช้งานหลายบทบาท ทำให้การควบคุมลำดับงานมีความซับซ้อน

4) การแสดงผลและประสบการณ์ใช้งานบางหน้าจอยังต้องปรับให้เหมาะสมกับอุปกรณ์ที่แตกต่างกัน โดยเฉพาะการใช้งานบนมือถือ

### 5.3.2 สาเหตุของปัญหาที่เกิดขึ้น
1) ข้อมูลมีการเปลี่ยนแปลงระหว่างขั้นตอนการใช้งาน และมีการอ้างอิงจากหลายจุด ทำให้เกิดความคลาดเคลื่อนในบางสถานการณ์

2) ความแตกต่างของค่ากำหนดระบบ แพ็กเกจที่ติดตั้ง และการตั้งค่าสภาพแวดล้อม ทำให้ผลลัพธ์ของบางฟังก์ชันไม่สม่ำเสมอ

3) เงื่อนไขทางธุรกิจของงานจองมีรายละเอียดสูงและปรับตามข้อกำหนดหน้างานจริง ส่งผลให้ตรรกะการเปลี่ยนสถานะซับซ้อนขึ้น

4) ข้อจำกัดด้านขนาดหน้าจอและพฤติกรรมผู้ใช้งานที่หลากหลาย ทำให้รูปแบบการนำเสนอข้อมูลต้องปรับจูนเพิ่มเติมในบางส่วน

### 5.3.3 แนวทางการแก้ไขปัญหา
1) เพิ่มกระบวนการตรวจสอบความถูกต้องของข้อมูล (validation) ก่อนยืนยันธุรกรรม และกำหนดข้อความแจ้งเตือนกรณีข้อมูลขัดแย้งให้ชัดเจน

2) กำหนดมาตรฐานการตั้งค่าระบบด้วย environment variables และตรวจสอบ dependencies ให้ตรงกันทุกสภาพแวดล้อม พร้อมทดสอบหลัง deploy ทุกครั้ง

3) นิยาม state transition ให้ชัดเจนตามบทบาทผู้ใช้ และแยกตรรกะซับซ้อนออกเป็นชั้นบริการ (service layer) เพื่อให้ง่ายต่อการดูแลรักษา

4) ปรับปรุงส่วนติดต่อผู้ใช้ตามแนวทาง mobile-first และทดสอบหลายขนาดหน้าจอเพื่อให้การใช้งานมีความต่อเนื่องและเข้าใจง่าย

## 5.4 ข้อเสนอแนะ
1) ควรเพิ่มการทดสอบประสิทธิภาพภายใต้ภาระงานสูง (performance/load test) เพื่อประเมินความพร้อมของระบบเมื่อมีผู้ใช้งานจำนวนมากในเวลาเดียวกัน

2) ควรจัดทำเอกสาร API ในรูปแบบมาตรฐานให้ครบถ้วน เพื่อรองรับการส่งมอบงาน การดูแลรักษา และการเชื่อมต่อระบบในอนาคต

3) ควรพัฒนาเครื่องมือเฝ้าระวังระบบ เช่น การบันทึกเหตุการณ์เชิงโครงสร้างและการแจ้งเตือนอัตโนมัติ เพื่อลดระยะเวลาในการตรวจพบและแก้ไขปัญหา

4) ควรต่อยอดรายงานเชิงวิเคราะห์สำหรับผู้บริหาร เช่น แนวโน้มการใช้ทรัพยากร ช่วงเวลาความต้องการสูง และประสิทธิภาพขั้นตอนอนุมัติ

5) ควรกำหนดตัวชี้วัดบริการ (SLA) ของขั้นตอนสำคัญ และทบทวนความต้องการร่วมกับผู้ใช้งานเป็นระยะ เพื่อให้ระบบปรับตัวได้ทันต่อบริบทการทำงานที่เปลี่ยนแปลง
